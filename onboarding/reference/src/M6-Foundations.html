Foundations: observe, shape, reach

Three small libraries carry most of the ecosystem on their backs. Sinal lets everything report what it's doing. JSON Blueprint describes the shape of data at every boundary. HTTP Gun is the single, bounded door to the network.

Sinal · typed telemetry

Report facts without slowing the work

You define an event once, with typed fields. Code emits it; observers react to it. Underneath, it's the same :telemetry registry Erlang and Elixir libraries already share, so their handlers can listen too. Observers normally run inside the emitting process. If they're slow, route them through a bounded forwarder.

Real time

Emit request.finished, live

A request handler emits an event for every request it finishes. Attach a slow observer, then compare running observers inline against routing them through a bounded forwarder. To make it visible, this forwarder holds 12 events; the real default is 1,024.

{{lvNote}}
Two rules from the README: event names become permanent BEAM atoms, so write them in source code and never build them from input. And forwarding is best effort: never use a telemetry event as proof that something happened. That's what durable records are for.
JSON Blueprint · data shapes

One codec, three faces

A codec describes a Gleam type's JSON shape: which fields exist, which are optional, which values are allowed. From that one definition you get an encoder, a strict decoder and a JSON Schema. LLM Wire, Relay, Fabric and Decisions all accept codecs, which is why the schema a model sees always matches the decoder that checks its answer.

HTTP Gun · the network

A client that tells the truth

HTTP Gun moves bytes, enforces limits and reports exactly what happened. It deliberately doesn't interpret statuses, retry, follow redirects or speak protocols like SSE: those belong to adapters such as LLM Wire, or to your app. Click a part of the client to see its job.
