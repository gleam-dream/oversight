# Relay Wave 2 independent implementation review

## Verdict

- **FAIL — the partial checkpoint is not accepted as a correct Wave 2 subset.** `WAVE-2-REPORT.md` correctly declines full Wave 2 acceptance and identifies substantial retained scope. The delivered resource, prompt, completion, logging, stdio, and runtime claims nevertheless contain correctness defects that block acceptance of the implemented subset.
- The official MCP conformance harness was not run. The local schema gate covers five authored messages and omits every newly delivered resource, prompt, and completion result reviewed below.

## Findings

- **HIGH · Six delivered service results violate the frozen `2026-07-28` schema.** The generic service encoders omit mandatory cache and result fields ([`src/relay/protocol/v2026_07_28.gleam:756`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:756), [`src/relay/protocol/v2026_07_28.gleam:778`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:778), [`src/relay/protocol/v2026_07_28.gleam:790`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:790), [`src/relay/protocol/v2026_07_28.gleam:800`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:800), [`src/relay/protocol/v2026_07_28.gleam:814`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:814)). Independent validation of the emitted shapes against the pinned fixture rejected `ListResourcesResultResponse`, `ListResourceTemplatesResultResponse`, and `ListPromptsResultResponse` for missing `cacheScope`; `ReadResourceResultResponse` for missing its required cache/result fields; and `GetPromptResultResponse` and `CompleteResultResponse` for missing `resultType`. The gate's required-definition set covers only discovery, tools/list, tool results, and unsupported-version errors ([`scripts/relay_schema_check.py:16`](/code/gleam-dream/relay/scripts/relay_schema_check.py:16)); service tests assert string fragments rather than schema conformance ([`test/relay/service_test.gleam:86`](/code/gleam-dream/relay/test/relay/service_test.gleam:86)). Proposed `(in-place-fix, now)`.

- **HIGH · The modern logging and capability contract is represented incorrectly.** The router admits `logging/setLevel` and mutates process-wide server state ([`src/relay/protocol/v2026_07_28.gleam:285`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:285), [`src/relay/server.gleam:572`](/code/gleam-dream/relay/src/relay/server.gleam:572)), but the frozen schema contains no `LoggingSetLevelRequest` and states that per-request `io.modelcontextprotocol/logLevel` replaces that RPC. Metadata parsing ignores the modern field ([`src/relay/protocol/v2026_07_28.gleam:519`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:519)). Discovery also always advertises `logging` although notification emission is deferred, and it cannot advertise `completions` even when a completion handler exists ([`src/relay/server.gleam:371`](/code/gleam-dream/relay/src/relay/server.gleam:371), [`src/relay/protocol/v2026_07_28.gleam:715`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:715)). The implemented-capability claim in `WAVE-2-REPORT.md` is therefore false for logging and incomplete for completion. Proposed `(in-place-fix, now)`.

- **HIGH · Broken stdout still cannot promptly terminate an idle stdio transport.** Runtime writes report failure through `write_error_box` ([`src/relay/transport/stdio.gleam:275`](/code/gleam-dream/relay/src/relay/transport/stdio.gleam:275)), but the main loop checks that mailbox only after the synchronous stdin reader returns ([`src/relay/transport/stdio.gleam:337`](/code/gleam-dream/relay/src/relay/transport/stdio.gleam:337), [`src/relay/transport/stdio.gleam:388`](/code/gleam-dream/relay/src/relay/transport/stdio.gleam:388)). If a worker writes after the caller has stopped sending input, stdout can fail while the server remains blocked in `file:read`. The regressions exercise a direct writer failure and an oversized-frame refusal write ([`test/relay/stdio_test.gleam:172`](/code/gleam-dream/relay/test/relay/stdio_test.gleam:172)); neither reproduces an asynchronous broken pipe with open, idle stdin. The prior finding remains partially open in behavior as well as evidence. Proposed `(in-place-fix, now)`.

- **HIGH · Duplicate exchange admission leaks runtime capacity.** `ReceiveFrame` increments `live_exchanges` before calling the reducer ([`src/relay/runtime.gleam:198`](/code/gleam-dream/relay/src/relay/runtime.gleam:198)). The reducer returns no effects for a reused exchange ID ([`src/relay/server.gleam:327`](/code/gleam-dream/relay/src/relay/server.gleam:327)), so no `CloseExchange` effect decrements the count. Repeating one exchange ID up to `max_live_exchanges` makes the next fresh request fail with `TooManyLiveExchanges` even though only one exchange was ever admitted. The duplicate test exercises only the pure reducer ([`test/relay/race_test.gleam:146`](/code/gleam-dream/relay/test/relay/race_test.gleam:146)) and cannot detect owner accounting. Proposed `(in-place-fix, now)`.

- **HIGH · Deferred multi-round inputs are accepted and silently treated as first-round calls.** The tools/call parser explicitly rejects `requestState` and `inputResponses` ([`src/relay/protocol/v2026_07_28.gleam:633`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:633)), but resource/read and prompts/get decode only their ordinary fields and ignore the same schema-valid continuation fields ([`src/relay/protocol/v2026_07_28.gleam:364`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:364), [`src/relay/protocol/v2026_07_28.gleam:375`](/code/gleam-dream/relay/src/relay/protocol/v2026_07_28.gleam:375)). Such a request invokes the ordinary handler without its continuation state. This contradicts the report's statement that continuation inputs reject and can repeat application work with changed semantics. Proposed `(in-place-fix, now)`.

## Prior-review closure

- Exact Blueprint numeric preservation, bounded raw stdio reads, admitted-request observation, schema admission, malformed metadata rejection, crash redaction, Git provenance, and typed startup return paths have direct source and passing regression evidence.
- Broken stdout remains open as described above. The process/race evidence improved with repeated cancellation/completion cases, mailbox assertions, split UTF-8, multi-frame input, frame-limit, and EOF child tests. Broken owner/child/stdout behavior and bounded process-count cleanup remain unproved, as the implementation report states.
- The Mist adapter owns bounded request reads and basic header admission, but it buffers all events before constructing SSE and stops the runtime before delivery ([`src/relay/transport/http.gleam:369`](/code/gleam-dream/relay/src/relay/transport/http.gleam:369), [`src/relay/transport/http.gleam:484`](/code/gleam-dream/relay/src/relay/transport/http.gleam:484)). Live delivery, disconnect cancellation, and response backpressure remain incomplete and must not support a streaming-conformance claim.
- The Gun boundary keeps MCP JSON parsing in Gleam, applies stream correlation, one-chunk flow credit, response bounds, a monotonic deadline, cancellation, connection reuse, and TLS peer verification ([`src/relay_gun_ffi.erl:9`](/code/gleam-dream/relay/src/relay_gun_ffi.erl:9), [`src/relay_gun_ffi.erl:28`](/code/gleam-dream/relay/src/relay_gun_ffi.erl:28)). Local evidence does not cover owner death, an explicit cancel race, TLS, malicious response correlation, or response-header/version agreement. The client remains an HTTP tools subset rather than the requested HTTP-and-stdio typed client.
- Authorization claims are honest: the public documentation marks both transports unprotected and warns against untrusted deployment. Protected routing remains deferred.
