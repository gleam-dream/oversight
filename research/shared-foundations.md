# Shared foundations: codecs and instrumentation

## Status and recommendation

- **Update `json_blueprint`; do not replace it.** Version 1.7.1 already moved beyond the referenced 1.1.0 release, but it still couples a schema to only a decoder and leaves the encoder separate. A 2.0 release should make one opaque `Codec(a)` the authority for JSON decoding, JSON encoding, and JSON Schema generation.
- **Build Sinal as a typed facade over `telemetry` 1.4.2; remove the actor-per-event runtime.** `telemetry` already supplies synchronous dispatch, a process-independent handler registry, failure isolation, and the interoperability expected by BEAM libraries. Sinal should add typed event descriptors and checked dynamic boundaries without replacing those semantics.
- **Keep the two foundations separate.** Both use the rule that one value owns producer and consumer agreement, but their representations, error types, and operational laws differ. Packages depend directly on the foundation they need; a general `common` package would only hide those differences.

## JSON Blueprint evidence

- The current Hex release is [`json_blueprint` 1.7.1](https://hex.pm/packages/json_blueprint), whereas the original reference was [1.1.0](https://json-blueprint.hexdocs.pm/1.1.0/). The [1.1.0 source](https://github.com/lostbean/json_blueprint/blob/v1.1.0/src/json/blueprint.gleam) imports the removed pre-0.60 `gleam/dynamic` decoder API while declaring `gleam_stdlib >= 0.34.0 and < 2.0.0`, so allowed dependency resolution can select an incompatible standard library.
- The [1.7.1 source](https://github.com/lostbean/json_blueprint/blob/v1.7.1/src/json/blueprint.gleam) supports current dependencies by vendoring the deleted decoder implementation. Its public `Decoder(a)` contains a decoder, schema definition, and references, while union and optional encoders remain independent functions; the type system therefore cannot prove that the encoder and decoder describe the same JSON language.
- The [1.7.1 schema implementation](https://github.com/lostbean/json_blueprint/blob/v1.7.1/src/json/blueprint/schema.gleam) declares Draft 7 but emits `$defs`, `prefixItems`, `minContains`, and `maxContains`, which are from later dialects. `decode0` accepts every input while documenting an empty closed object, and `optional_field` accepts explicit `null` while its schema makes the field optional without making its value nullable. These are observed source mismatches, not inferred risks.
- [`glon` 1.0.0](https://hex.pm/packages/glon) is the closest design reference because its opaque [`JsonSchema(a)`](https://glon.hexdocs.pm/glon.html) carries schema and decoder together and supports object fields and tagged unions. It has no encoder, and its `map: fn(a) -> b` is necessarily decoder-only, so adopting it would preserve the missing round-trip guarantee.
- [`castor` 2.1.0](https://hex.pm/packages/castor) is the stronger runtime JSON Schema parser and builder. It represents schemas rather than application values, so it should be an optional parser or validation oracle instead of the typed codec core.

## JSON Blueprint contract

- The first 2.0 release should expose an opaque `Codec(a)` with `decode: fn(Json) -> Result(a, DecodeError)`, `encode: fn(a) -> Result(Json, EncodeError)`, and one schema definition in one selected dialect. Encoding must be fallible because a constrained `Codec(Int)` cannot encode every `Int`; a total encoder is valid only when the Gleam type itself represents the codec's complete valid-value set. The initial vocabulary should cover primitives, lists, nullable values, closed records, optional fields, enums, and tagged unions; recursive references, arbitrary schema keywords, and parsed runtime schemas can follow only after the core laws pass.
- A transform must be bidirectional. `imap(codec, decode_map: fn(a) -> b, encode_map: fn(b) -> a)` supports total isomorphisms that preserve the wire language, while a refinement may reject values only when it also supplies an equivalent schema constraint and checks encoding. Arbitrary semantic validation belongs in a domain parser after codec decoding because a validation that the schema cannot express would break decoder/schema agreement; the current one-way `map` cannot remain on `Codec` because it cannot synthesize an encoder for `b`.
- A parsed `RuntimeSchema` must remain separate and return `TypedValue` or raw JSON by default. A runtime document can be checked against a caller-supplied codec for a pre-existing type, but it cannot create a new named Gleam type after the consuming application has compiled; code generation before application compilation is the route from a document to new named types.
- Code generation should be a companion development tool invoked with [`gleam run -m`](https://gleam.run/documentation/command-line-reference/), not a hidden compile phase. It should read a bounded schema subset and write reviewable Gleam modules that declare types and codecs; unsupported keywords must fail generation, and the consuming application must compile the generated modules. Committed output avoids requiring generated code before the generator dependency can compile.
- Migration can preserve 1.x call sites through deprecated adapters: `decoder(codec)`, `encoder(codec)`, and `schema(codec)`. Existing hand-written decoder and encoder pairs move into `Codec` only after agreement tests pass; 1.x schema output is not carried forward silently because its dialect and acceptance mismatches require an explicit compatibility mode or a major-version correction.

## JSON laws and compiler probes

- For every valid `x`, `encode(x) == Ok(j)` implies `decode(j) == Ok(x)` and schema validation accepts `j`; invalid values must return `EncodeError`. For every JSON value `j` in the codec's declared wire vocabulary, schema validation succeeds exactly when codec decoding succeeds. Domain validation outside the codec is excluded from this equivalence; for accepted non-canonical input, re-encoding the decoded value must succeed and validate.
- Implement a minimal record codec whose required and optional fields need both constructor inputs and field getters, with no `todo`, panic, unsafe cast, or placeholder FFI on the claimed path. Separate expected-failure fixtures must reject an omitted encoder getter, a getter of the wrong parent type, and a decoder-only transform for the intended compiler diagnostic.
- Compile tagged-union codecs and a heterogeneous tool list. Each tool should erase only at the collection boundary into a closure such as `fn(Json) -> Result(Json, Error)` while retaining its own `Codec(input)` and `Codec(output)` internally; an attempted `List(Codec(a))` across different `a` must fail.
- Construct `fn(RuntimeSchema) -> Result(RuntimeCodec, Error)`, where `RuntimeCodec` yields `TypedValue`, without unfinished or unsafe bodies. Do not treat compilation of `fn(RuntimeSchema) -> Codec(a)` as evidence that it is implementable because `todo` or panic can inhabit that signature; acceptance requires a total construction from the stated inputs, and the type parameter `a` has no such source.
- Validate emitted schemas with a pinned independent Draft 2020-12 oracle and run decoder/schema differential cases for missing, `null`, extra, overlapping-union, and recursive values. A disagreement blocks 2.0 rather than becoming a documented exception.

## Sinal evidence

- [`telemetry` 1.4.2](https://hex.pm/packages/telemetry) calls every handler in the emitting process, does not guarantee handler order, catches handler exceptions, detaches the failing handler, and emits `[telemetry, handler, failure]`; these behaviors are explicit in the [pinned implementation](https://github.com/beam-telemetry/telemetry/blob/v1.4.2/src/telemetry.erl). Its handler table serializes writes through a `gen_server`, while dispatch reads ETS in the caller and can be switched to `persistent_term` with `persist/0`.
- An actor per event would move execution to another process and therefore add mailbox ordering, overload, loss, lifecycle, and supervision choices. Those are event-system semantics rather than a typed version of `telemetry`; they also prevent existing Erlang and Elixir handlers from observing Sinal events without a second bridge.
- [`opengleametry` 2.0.0](https://hex.pm/packages/opengleametry/2.0.0) and [`glotel` 1.0.1](https://hex.pm/packages/glotel/1.0.1) are direct Gleam facades over `opentelemetry_api`. Their published [OpenGleametry FFI](https://hex.pm/packages/opengleametry/2.0.0/files/src/opengleametry_ffi.erl) and [glotel span module](https://hex.pm/packages/glotel/1.0.1/files/src/glotel/span.gleam) create and mutate spans; they do not implement generic event registration or `telemetry` compatibility, so neither replaces Sinal.
- [`opentelemetry_telemetry` 1.1.2](https://hexdocs.pm/opentelemetry_telemetry/) already converts conventional `telemetry` start, stop, and exception events into OpenTelemetry spans. Sinal gains this path automatically by emitting real `telemetry` events; an OTel package belongs in an optional downstream adapter or application, not Sinal core.

## Sinal contract and scope

- The first release should provide opaque `Event(measurements, metadata)` descriptors, `execute`, `attach`, `attach_many` only for descriptors with the same two types, and `detach`. A descriptor owns an atom-list event name plus map encoders and decoders; `execute` encodes and calls `telemetry:execute/3`, while `attach` registers a static Erlang handler whose configuration carries the Gleam decoders and closure.
- Event names should accept `List(atom.Atom)` at the low-level boundary. A string convenience constructor may create atoms only from trusted application constants and must state the VM atom-table limit documented by [`gleam/erlang/atom`](https://gleam-erlang.hexdocs.pm/gleam/erlang/atom.html); foreign or user-controlled strings must never create atoms.
- Static agreement applies when emitter and handler share the same opaque descriptor. Two independently defined descriptors can reuse the same raw atom name with different types, and a foreign emitter can publish any maps; Sinal cannot make either case globally type-safe. Every handler therefore decodes at the callback boundary, and a mismatch must detach the handler and surface the standard telemetry failure event instead of repeatedly dropping malformed events.
- The first release should implement events first, then add typed spans only after an oracle comparison with `telemetry:span/3`; publication of the planned event-and-span slice waits for both stages. The span design must preserve start/stop/exception names, native-time measurements, `telemetry_span_context`, re-raising behavior, and the rule that stop metadata independently contains fields needed by stop handlers. OpenTelemetry export, asynchronous forwarding, metrics aggregation, and handler supervision remain separate adapters.
- The dependency direction is `relay|fabric|saga|grind -> json_blueprint` where JSON contracts exist, and each instrumented package `-> sinal -> telemetry`. An optional `sinal_otel -> sinal + opentelemetry_telemetry/opentelemetry_api` may follow; neither foundation depends on the other.

## Sinal laws and decision experiment

- `decode_measurements(encode_measurements(m)) == Ok(m)` and the corresponding metadata law hold for every descriptor. A raw `telemetry` handler must observe the same atom name and maps that Sinal emits, and a Sinal handler must run in the emitter process before `execute` returns.
- Duplicate handler identifiers must return `AlreadyExists`; detach must report absence; callback failure and decode failure must remove the registration and emit the upstream failure event; multiple handlers must expose no order guarantee. These laws copy upstream behavior rather than inventing stronger guarantees.
- Build one throwaway Erlang-target probe with two typed descriptors, one foreign raw event, a static FFI handler whose config contains a Gleam closure, and a deliberate decoder mismatch. Compare process identity, callback timing, duplicate registration, detachment, failure event content, and behavior before and after `telemetry:persist/0` against `telemetry` 1.4.2. If a Gleam closure cannot safely live in handler config, or decoded failure cannot retain upstream isolation without per-event processes, reconsider the facade; otherwise the actor design is rejected.

## Verification record

- The pinned `json_blueprint` 1.1.0 and 1.7.1 archives, `telemetry` 1.4.2 archive, and published `opengleametry` 2.0.0 and `glotel` 1.0.1 Hex archives were inspected locally. JSON Blueprint and telemetry tests were read; the two OpenTelemetry facade archives contain no tests. No suite was run during this source-inspection pass, so the conclusions remain source-based until the planned compiler and behavior probes run.
