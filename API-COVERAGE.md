# Public API exploration coverage

## Purpose

- This audit maps the complete capability intent in the six original package designs to the current ecosystem boundaries and interface laboratory. It also covers JSON Blueprint and the standalone LLM client because the ecosystem plan makes both independent public boundaries.
- This audit measures public type and interface exploration. It does not measure production implementation, protocol conformance, persistence correctness, fault recovery, performance, or package maturity.
- The [initial public API freeze](PUBLIC-API.md) selects intended package facades and resolves numeric representation, code-generation scope, and durable protocol visibility; it does not mark Open or Partial rows complete.
- A capability remains in scope when the current plan assigns it to another owner. Reassignment prevents duplicate engines; it does not delete the capability from the ecosystem.
- The source set is ([Fabric](fabric-design.md), [Grind](grind-design.md), [Relay](relay-design.md), [Saga](saga-design.md), [Sinal](sinal-design.md), [Warden](warden-design.md), [ecosystem plan](ECOSYSTEM-PLAN.md), [initial exploration](EXPLORATION.md), and every file under [`research/`](research/)). The current evidence source is the [interface laboratory](playground/interface_lab/README.md), with [refinement status](playground/interface_lab/REFINEMENT-STATUS.md) as the latest summary.

## Evidence rules

| Mark             | API exploration meaning                                                                                                                                                           |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Demonstrated** | A constructive representation and a named consumer exercise the stated public shape. A relevant negative fixture or pure probe checks the important distinction where one exists. |
| **Partial**      | A named consumer exercises part of the family, but another public distinction from the intended scope remains unrepresented.                                                      |
| **Open**         | The intended capability has no concrete consumer evidence for its public shape. A proposed signature or `todo` alone does not count.                                              |
| **Reassigned**   | The original design placed the capability here, while the current ecosystem plan assigns it to another owner. Coverage is measured under that owner.                              |
| **Excluded**     | The current scope explicitly excludes the capability. It creates no interface backlog unless the scope changes.                                                                   |

- Runtime obligations are recorded separately from API evidence. A runtime obligation does not reduce demonstrated API coverage, while a `todo` body does not increase it.
- Historical counts in [first findings](playground/interface_lab/FINDINGS.md) and [stress tests](playground/interface_lab/STRESS-TESTS.md) are superseded by the latest refinement status. Their consumer scenarios still identify intended use.
- The laboratory is one disposable Gleam package. Source-isolated consumers check import direction inside that package; they do not prove independent Hex package builds or final distribution boundaries.

- Laboratory Blueprint imports used by ordinary serialization are prototype convenience, not a production dependency requirement. Prefer standard Gleam JSON encoders/decoders outside JSON Schema-aware paths; optional reusable codecs remain schema-independent. Existing evidence rows describe the laboratory as run, not a mandate to preserve its dependency graph. Blueprint’s exact-number policy applies within its schema/value model.

## Completion criteria for API exploration

- **Bounded progress:** A broad family may be split into named subfamilies so an exercised interface can be accepted while its unfinished siblings remain visible. Splitting a row does not remove any intended capability.
- **Inventory completion:** Every capability family above is marked Demonstrated, Reassigned, or Excluded. A Partial or Open row prevents a claim that the full public API exploration is complete.
- **Consumer completion:** Every in-scope family has at least one source-isolated positive consumer. Every safety distinction that the Gleam compiler can enforce has one negative fixture that fails for the intended diagnostic.
- **Constructive completion:** Every claimed static guarantee has a total representation on the exercised path. A `todo`, panic, unsafe cast, placeholder FFI, or public phantom parameter cannot be its only construction proof.
- **Pairwise composition completion:** Every integration row above has a consumer using public contracts only. No combined demonstration may require a universal operation type, global request context, or access to another package's private representation.
- **Ownership completion:** Retry, cancellation, suspension, persistence, compensation, authorization, streaming resources, and observations each have one named owner at every cross-package boundary. The type surface preserves distinct outcomes where ownership changes.
- **Scope completion:** Initial and later capability families remain visible. An initial useful slice may defer a row, while it cannot redefine the declared package goal as complete.
- **Evidence separation:** The final coverage report lists API evidence and pending runtime evidence separately. API exploration may complete before conformance, differential, fault, benchmark, or production implementation work begins.
- **Packaging neutrality:** Laboratory module names do not create permanent packages. A new package boundary requires an independent consumer, dependency or target isolation, or release-cadence evidence beyond this interface audit.
